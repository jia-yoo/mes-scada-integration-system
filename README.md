## 🎯 주요 해결 과제

### 1. SCADA 연동 — TCP/IP 통신 불가 환경에서의 실시간 데이터 연계

**배경:** SCADA가 메인 시스템으로, MES 관리자 프로그램에서 현장 상황을 실시간으로 파악하려면 SCADA와 데이터를 주고받아야 했음. 그러나 SCADA 측이 TCP/IP 통신 구현이 불가하다고 하여 대안이 필요했음

**해결:**

- SCADA가 업데이트하는 DB 테이블에 트리거를 설정
- 트리거 발동 시 MES 관리자 프로그램 로직이 자동으로 실행되는 구조 구현

**결과:** 데이터 누락 0건, 실시간 현장 데이터 연계 달성

---

### 2. 대용량 PLC 수집 데이터 처리 및 성능 개선

**배경:** 14개 포인트에서 30초마다 PLC 수집 데이터가 들어오며, 하루 약 4만 건의 데이터가 누적되는 환경

**문제:** 데이터 누적으로 인해 30일치 조회 응답시간이 5분 이상 소요

**해결:**

- 스케줄러를 활용해 매일 밤 당일 수집 데이터를 파일로 변환·저장 후 DB에서 삭제하는 아카이빙 구조 적용. DB 조회 대신 파일 리딩으로 전환하여 조회 성능 개선.

**결과:** 조회 응답시간 5분 이상 → 수초 이내로 단축 (약 98% 개선)

---

### 3. 조인 쿼리 제약으로 인한 데이터 접근 불완전성 해결

**문제:** SCADA 개발 프로그램 특성상 복잡한 조인 쿼리 사용이 불가하여, 관리자 프로그램에 저장된 설비 기준정보·설정값 등 필요한 데이터 전체를 한 번에 가져갈 수 없었음. 일부 데이터만 제공 가능한 상황

**해결:**

- SCADA에서 필요한 모든 데이터를 미리 조인한 DB View 설계
- SCADA는 단순 조회만으로 필요한 전체 데이터를 가져갈 수 있도록 구조 개선

**결과:** SCADA에서 필요한 데이터 전체 접근 가능, 데이터 접근 완전성 확보

---

### 4. PM 부재 환경에서의 프로젝트 관리

**배경:** SCADA 개발 담당자가 PM 역할을 겸했으나 실질적으로 PM 기능을 하지 못하는 상황. 각 담당자들이 서로 다른 내용을 알고 있어 의사소통 문제가 반복되며 프로젝트가 지지부진하게 진행됨

**해결:**

- 정기 회의를 직접 제안하여 모든 담당자가 한 자리에서 소통하는 구조 구축
- 모듈·챕터 단위로 완료될 때마다 피드백 루프를 운영하여 합의 내용 즉시 업데이트
- 커뮤니케이션 방식을 일관성 있게 정리하여 혼선 방지

**결과:** 합의 번복 0건, 일정 내 납기 완료

## 💡 회고

- TCP/IP 통신이 불가한 제약 조건에서 DB 트리거라는 우회 구조를 적용해, 제약 안에서 해결책을 찾는 경험을 했습니다.
- 성능 저하 문제를 단순 쿼리 튜닝이 아닌 아카이빙 구조 변경으로 근본적으로 해결한 경험이었습니다.
- PM 없이 정기 회의와 피드백 루프를 직접 만들어 프로젝트를 납기 내 완료한 경험을 통해, 개발 외적인 문제도 구조적으로 접근하는 역량을 키웠습니다.
